## 오류 및 원인

### 1. `mcpServers`를 settings.json에 등록하려 했으나 스키마 오류
- **증상**: Claude Code가 settings.json에서 `mcpServers` 키를 인식하지 못함
- **원인**: Claude Code는 MCP 서버를 `~/.claude/.mcp.json`에 별도 등록해야 함. settings.json은 다른 용도
- **해결**: `C:\Users\smhrd\.claude\.mcp.json` 파일 새로 생성
  ```json
  {
    "mcpServers": {
      "ashfox": {
        "type": "http",
        "url": "http://127.0.0.1:8787/mcp"
      }
    }
  }
  ```

### 2. PowerShell `$args` 예약어 충돌
- **증상**: 함수 파라미터를 `$args`로 쓰자 PowerShell이 자동 변수와 혼동하여 예상치 못한 동작
- **원인**: `$args`는 PowerShell의 자동 변수(자동으로 모든 미명시 인자를 담는 배열). 함수 파라미터명으로 사용 불가
- **해결**: `$a`, `$body` 등 다른 이름으로 변경

### 3. PowerShell `AC` 별칭 충돌
- **증상**: `AC` 함수(Add-Cube 의도)를 호출하면 `Add-Content` 실행됨
- **원인**: PowerShell에 `AC`는 `Add-Content`의 기본 별칭
- **해결**: 함수명을 `Add-Bone`, `Add-Cube` 등 전체 이름 사용

### 4. Revision 추출 경로 오류
- **증상**: `$r.result.structuredContent.project.revision`으로 추출하면 null
- **원인**: `add_bone`의 응답 구조는 `structuredContent.revision` (project 중첩 없음)
- **해결**: `$r.result.structuredContent.revision`으로 수정
  ```powershell
  return $r.result.structuredContent.revision
  ```

### 5. `fill_rect` — "invalid texture op" 오류
- **증상**: `fill_rect` op 사용 시 "invalid texture op (SuitMan)" 에러
- **원인**: `x, y, width, height` 파라미터를 생략하면 서버가 연산을 거부함
- **해결**: 항상 명시적으로 지정
  ```powershell
  op=@{ op="fill_rect"; x=0; y=0; width=64; height=64; color=$color }
  ```

### 6. `face=""` 빈 문자열로 에러
- **증상**: target 해시테이블에 `face=""`를 포함시키면 오류
- **원인**: 빈 문자열은 유효하지 않은 face 값으로 처리됨
- **해결**: face가 null이거나 빈 문자열이면 target에 아예 포함시키지 않음
  ```powershell
  if ($face) { $t["face"] = $face }
  ```

### 7. `assign_texture` — 텍스처를 찾지 못하는 오류
- **증상**: 기존 프로젝트를 재사용할 때 assign_texture 실패
- **원인**: `ensure_project`는 신규 프로젝트 생성 시에만 동명 텍스처를 자동 생성함. 기존 프로젝트 재사용 시에는 텍스처가 없을 수 있음
- **해결**: 기존 프로젝트를 삭제하고 새로 생성 (ensure_project → 자동 텍스처 생성 유도)

### 8. 해시테이블 내부 산술 연산 오류
- **증상**: `@($s.x - $hw, ...)` 형태의 배열 생성 시 오류
- **원인**: 해시테이블 값은 object 타입이라 직접 배열 생성자 안에서 산술 연산이 실패함
- **해결**: 먼저 변수에 계산값 저장 후 배열에 삽입
  ```powershell
  $x1 = $s.x - $hw
  $from = @($x1, $s.y, $s.z)
  ```

### 9. `stem` 큐브 이름 충돌
- **증상**: "stem" 이름의 큐브 추가 시 이미 존재한다는 오류
- **원인**: 같은 세션에서 이전 시도의 큐브가 이미 등록된 상태
- **해결**: 이름을 `stalk`으로 변경하거나, 프로젝트를 새로 생성

### 10. paint_faces — targets/ops 배열이 아닌 target/op 단수
- **증상**: `$.target is required` 오류
- **원인**: 실제 스키마는 `target` (단수 object), `op` (단수 object)
- **해결**: 배열 아니라 단일 객체로 전달
  ```powershell
  target = @{ cubeName="candle" }          # face 생략 = 전체 6면
  op     = @{ op="fill_rect"; x=0; y=0; width=64; height=64; color="#F0E6C8" }
  ```
- **보너스**: `target.face` 생략 시 전체 6면을 1번 호출로 처리 (30호출 → 5호출)

### 11. assign_texture — cube 아닌 cubeNames 배열
- **증상**: `$.cube is not allowed` 오류
- **원인**: 파라미터명이 `cubeNames` (복수 배열)
- **해결**: `cubeNames=@("candle","wax_top","wick","flame_ns","flame_ew")`

### 12. ensure_project — 활성 프로젝트를 이름 무관하게 재사용
- **증상**: `ensure_project "Candle"` 인데 Banana 프로젝트가 reused됨
- **원인**: 기본 동작이 활성 프로젝트 재사용. format_and_name 매칭 아님
- **해결**: 새 프로젝트 강제 생성:
  ```powershell
  match="format_and_name"; onMismatch="create"; onMissing="create"; ifRevision=$rev
  ```

### 13. ensure_project — ifRevision 필수
- **증상**: `ifRevision is required` 오류
- **원인**: ensure_project도 뮤테이션으로 취급되어 ifRevision 필수
- **해결**: Rev()로 revision 먼저 획득 후 포함

### 14. render_preview — mode 필수 파라미터
- **증상**: `$.mode is required` 오류
- **원인**: 빈 args로 호출하면 mode가 없어서 실패
- **해결**: `mode="fixed"` (단일 앵글) 또는 `mode="turntable"` (회전 시퀀스)
  ```powershell
  Mcp "render_preview" @{ mode="fixed"; output="single"; angle=@(25,45,0); saveToTmp=$true }
  ```

### 15. 동일 크기 큐브 겹침 → Z-파이팅 (텍스처 반짝거림)
- **증상**: 같은 크기·위치의 큐브 두 개를 겹치면 텍스처가 번갈아 깜빡임
- **원인**: Z-파이팅 — 렌더러가 어느 면이 앞인지 판단 못해 매 프레임 다른 큐브를 그림
- **해결**: 바깥 큐브에 `±0.001` 미세 크기 차이 부여
  ```
  안쪽: from=[0, 0, 0]           to=[8, 8, 8]
  바깥: from=[-0.001,-0.001,-0.001]  to=[8.001, 8.001, 8.001]
  ```
- **권장 범위**: 0.001 ~ 0.01 (더 크면 틈이 시각적으로 보임)
